AI becomes an infrastructure problem: egress boundaries, resource labels, and China's full-stack scaling

Since yesterday, the abstract idea of “proof before scale” has turned into a more concrete architecture trend: the control layer is becoming a product in its own right. Alibaba is stretching its AI strategy from models through proprietary chips to more than 20 GW of planned cloud capacity. The EU is making energy and water metrics for large data centers more comparable. And for agents, the operational boundary is visible directly in the data path: AWS/Benchling describes default-deny egress including DNS filtering, while the ZCode case shows what happens when a code-indexing feature moves local repositories to cloud infrastructure unexpectedly. Analysis: the next competitive advantage is not just a stronger model, but the ability to measure and control compute, resources, and data flows.

What changed since yesterday?

Yesterday China's hardware story was mainly about packaging capacity. Today Alibaba shows the other side: one provider is trying to control model architecture, accelerator, supernode, and cloud capacity as a single platform.

Why it matters

AI economics increasingly depends on whether models, chips, networks, and power capacity can scale together. Vertical integration can reduce supply-chain exposure and enable cross-layer optimization—but it also raises capital intensity and dependence on a roadmap that still has to ship.

Signal vs. Hype

INFRASTRUCTURE GOVERNANCEEU · DATA CENTERS · ENERGY · WATERConfirmed · Primary

The EU is turning data-center efficiency into a comparable metric

The European Commission has set out a common rating scheme for individual data centers above 500 kW of IT power. It is designed to make actual energy and water use plus contributions to the energy system—such as waste-heat reuse and flexibility—more transparent. The first labels are expected in 2027; the legal act first goes through a two-month scrutiny period by Parliament and Council. In parallel, the Commission is consulting on minimum performance standards. Those minimums are not adopted today.

🧠 Models, Agents & Engineering

AGENT SECURITYBEDROCK AGENTCORE · BENCHLINGPrimary deployment report

The real agent sandbox ends at the network: DNS is part of the security model

AWS and Benchling describe a production architecture for AI-generated scientific code across thousands of tenants. Untrusted code runs in a separate AWS account in AgentCore Code Interpreter VPC mode. The decisive layer is egress: no Internet Gateway or NAT, a DNS Firewall with allowlist/block-all logic, VPC endpoint policies, and short-lived job-specific STS credentials. Benchling reports more than 600 code-execution sessions per day and more than 250 distinct tenants per week since early April, with no security incident or cross-tenant leakage. These are customer/vendor-published operating metrics, not an independent audit.

Engineering Takeaway

Do not test agent sandboxes only for shell escape. Add CI fixtures for DNS tunneling, direct-IP egress, unauthorized object-store targets, credential reuse, and policy bypass. A process can be fully isolated and still exfiltrate data if network or DNS channels remain open.

Why it matters

Tool-using agents move the trust boundary from the prompt to the entire runtime. For enterprise agents, identity, egress, data access, and continuous adversarial testing belong in the same control plane.

Signal vs. Hype

Signal: the architecture is concrete and reproducible: separate account, VPC isolation, DNS policy, endpoint policy, per-job credentials. Hype brake: “zero incidents” is a published customer claim and does not replace independent review or ongoing red-team testing.

CODING AGENTSZ.AI · ZCODE · DATA EGRESSReported + Primary changelog

ZCode provides the counter-test: “indexing” can become cloud data movement

Reuters reports that Z.ai disabled parts of its ZCode coding assistant after developers said local repositories were transferred to Alibaba Cloud without expected consent. Z.ai attributed the incident to the default-enabled Codebase Indexing feature, apologized, and said the vulnerability was fixed. The public ZCode changelog for version 3.14.0 explicitly lists a fix for an “abnormal repository upload” issue. A complete independent technical root-cause report does not appear to be public yet.

What's new?

The case extends earlier coding-agent sandbox concerns into a different class: not only code execution can cross the boundary; repository snapshots, indexers, and convenience features can themselves become data channels.

Builder Action · Test now

For every coding agent: use a fresh install in a canary repository, capture outbound DNS/HTTP traffic, seed `.git` and LFS data with sentinels, toggle indexing/wiki/telemetry controls one by one, and verify that real network behavior changes accordingly.

Signal vs. Hype

Signal: the data-flow class is concrete and Z.ai documents a repository-upload fix. Hype brake: scope, affected-user count, and server-side deletion are not fully independently verified; no further assumptions are warranted.

🔬 Concept of the Day

DEFAULT-DENY EGRESS FOR AGENTS

Why sandbox ≠ data isolation

Intuition: a sandbox primarily answers: “What can this process do to CPU, filesystem, and host?” Egress control answers the equally important second question: “Where can this process's data flow?” An agent can fail to escape the host and still send source code, secrets, or customer content through DNS, HTTP, object storage, or an allowed tool endpoint.

Technical depth: default-deny egress starts with routing and security groups but does not end there. DNS is a data channel and needs its own rules. VPC/private endpoints need resource-specific policies. Credentials should be minimally privileged, short-lived, and scoped per job/session. And the rules need continuous adversarial fixtures—not just an architecture review once.

Practical example: give the agent a canary string that must never leave the system. Ask it to resolve a domain such as <canary>.example.invalid, contact a direct IP on port 443, and read a non-approved bucket. The platform passes only if every path is blocked and cleanly logged with provenance.

Connection to earlier concepts: this extends prior work on capability control, instruction authority, and hermetic coding-agent runtimes: policy must cover both what an agent may do and where its data may flow.
