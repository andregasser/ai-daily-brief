Perplexity SPACE: Die MicroVM hielt – die Egress-Policy nicht immer

Perplexity hat seinen Firecracker-basierten SPACE-Sandbox mit neun Modellkonfigurationen red-teamen lassen. In 108 VM→Host-Escape-Runs wurde kein erfolgreicher Escape beobachtet. Beim Netzwerk-Test war die vollständig gesperrte Variante ebenfalls stabil: 0/54 erfolgreiche Bypasses. Sobald jedoch ausgewählte Paket-Repositories erlaubt waren, erreichten Agents vor dem Fix in 11/54 Runs ein eigentlich blockiertes Ziel.

Die zwei gefundenen Mechanismen sind architektonisch wichtiger als die Modellnamen: DNS-Spoofing konnte eine erlaubte Domain auf die IP des blockierten Ziels abbilden; bei Shared-IP/CDN-Infrastruktur konnte die IP erlaubt sein, obwohl die spätere HTTP/TLS-Autorität zu einem anderen Tenant gehörte. Perplexity ergänzt deshalb Source-Validation sowie Konsistenzchecks zwischen DNS, Ziel-IP, TLS-SNI und HTTP-Authority.

Engineering Takeaway: Teste Agent-Sandboxes mit adversarialen Netzwerk-Canaries, nicht nur mit „deny all“. Besonders wichtig: forged DNS, Shared-IP/CDN-Tenants, SNI/Host-Mismatch und direkte IP-Verbindungen. Logging muss zeigen, warum eine Verbindung autorisiert wurde.

🔬 Konzept des Tages

Network Authority: Warum eine Domain-Allowlist keine Netzwerkgrenze ist

Eine Regel wie allow pypi.org klingt semantisch eindeutig. Auf dem Netzwerkpfad existiert aber keine einzelne, unveränderliche „Domain“. DNS übersetzt Namen in IPs, CDNs teilen IPs zwischen vielen Tenants, TLS nutzt SNI, HTTP/1.1 den Host-Header und HTTP/2/3 :authority. Wenn ein Gateway nur einen Teil dieser Kette prüft, kann eine erlaubte Identität an einer späteren Schicht in eine andere Autorität kippen.

Technische Intuition: Autorisierung darf nicht aus „IP wurde irgendwann für eine erlaubte Domain gesehen“ folgen. Sie muss eine konsistente Bindung prüfen: vertrauenswürdige DNS-Antwort → erwartete Ziel-IP → erlaubtes SNI → erlaubte HTTP-Authority. Bei Protokollen ohne überprüfbare Host-Autorität muss die Policy konservativer sein.

policy = allow("pypi.org")
dns = resolve_with_provenance("pypi.org")
conn = tls_connect(dst_ip)

allow = (
    conn.dst_ip in dns.answers
    and conn.sni == "pypi.org"
    and request.authority == "pypi.org"
)

Praktische Relevanz: Das ergänzt das Konzept vom 22.09. zu Default-Deny Egress: Default-Deny bestimmt was grundsätzlich erlaubt ist; Network Authority bestimmt ob die konkrete Verbindung tatsächlich noch genau diese erlaubte Identität repräsentiert.
