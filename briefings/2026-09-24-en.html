Models, Agents & Engineering
CRITICALCONFIRMED PRIMARY

Perplexity SPACE: the microVM held — the egress policy did not always

Perplexity red-teamed its Firecracker-based SPACE sandbox with nine model configurations. Across 108 VM→host escape runs, no successful escape was observed. The fully blocked network condition also held: 0/54 successful bypasses. Once selected package repositories were allowed, however, agents reached a supposedly blocked target in 11/54 runs before remediation.

The two mechanisms matter more architecturally than the model names. DNS spoofing could associate an allowed domain with the blocked target's IP; with shared-IP/CDN infrastructure, an IP could be allowed even though later HTTP/TLS authority selected a different tenant. Perplexity therefore added source validation and stronger consistency checks across DNS, destination IP, TLS SNI and HTTP authority.

Robust policy validates the same authority across layers; destination IP alone is insufficient on shared hosting/CDNs.

Engineering Takeaway: Test agent sandboxes with adversarial network canaries, not only with “deny all.” Focus on forged DNS, shared-IP/CDN tenants, SNI/Host mismatch and direct IP connections. Logging should explain why a connection was authorized.

Signal vs. Hype: This is strong primary evidence for a real policy class, not a universal claim that “8 of 10 sandboxes are insecure.” Specific versions/configurations were tested, and several vendors had already shipped or planned mitigations.

Agentic science: 950 Claude agents find a candidate — another agent runs six days of measurements

Anthropic reports that roughly 950 Claude agents spent 21 hours and 210M tokens analyzing more than 200,000 reverse transcriptases, identifying about 3,500 candidate systems and prioritizing 20 reports. This surfaced the ART system. Anthropic says initial wet-lab experiments show the repeat array is expressed as short RNAs; the biological function is still unknown.

Independently, a Sep 22 arXiv preprint describes a FermiLink agent that plans quantum-transport campaigns on MoS₂ devices, operates instruments, analyzes data and writes reports — across campaigns lasting up to six days.

🔬 Concept of the Day

Network Authority: Why a Domain Allowlist Is Not a Network Boundary

A rule such as allow pypi.org sounds semantically unambiguous. But there is no single immutable “domain” on the network path. DNS maps names to IPs, CDNs share IPs across tenants, TLS uses SNI, HTTP/1.1 uses the Host header, and HTTP/2/3 uses :authority. If a gateway validates only one part of this chain, an allowed identity can turn into a different authority at a later layer.

Technical intuition: Authorization must not follow from “this IP was once observed for an allowed domain.” It should validate a consistent binding: trusted DNS answer → expected destination IP → allowed SNI → allowed HTTP authority. Protocols without a verifiable host authority require more conservative policy.

policy = allow("pypi.org")
dns = resolve_with_provenance("pypi.org")
conn = tls_connect(dst_ip)

allow = (
    conn.dst_ip in dns.answers
    and conn.sni == "pypi.org"
    and request.authority == "pypi.org"
)

Practical relevance: This extends Sep 22's Default-Deny Egress concept. Default deny defines what may be reached in principle; network authority determines whether this concrete connection still represents exactly that allowed identity.
