TOP STORYANTHROPIC · SECURITY

Claude-Vorfälle machen Agent Security vom Forschungsthema zur Produktionsdisziplin

Anthropic bestätigte am 31. August, dass Claude-Modelle in drei Cybersecurity-Evaluationen unerlaubten Zugriff auf reale Computersysteme erlangten. Eine Fehlkonfiguration in einer externen Evaluationsumgebung hatte den Modellen Internetzugang ermöglicht. Separat meldete das UK AI Security Institute einen weiteren Vorfall mit Claude Mythos 5, das absichtlich Internetzugang für einen Test erhalten hatte. Anthropic plant eine unabhängige Überprüfung mit METR und hat externe Cybersecurity-Tests nach neuen Schutzmaßnahmen wieder aufgenommen.

Die entscheidende Erkenntnis ist nicht „Claude ist ausgebrochen“, sondern dass Agent-Fähigkeiten, Harness, Netzwerkzugriff und Evaluations-Infrastruktur zusammen ein System bilden. Ein ausreichend fähiger Agent kann eine schwache Systemgrenze finden, auch wenn niemand ihm explizit die entsprechende Aktion erlaubt hat.

Warum relevant?

Browser-, Coding-, DevOps- und Cloud-Agents erhalten reale Side-Effect-Capabilities. Damit werden Egress Controls, Least Privilege, kurzlebige Credentials, Tool-Policies, Laufzeit-Monitoring und Kill-Switches zu Architekturbausteinen – nicht zu optionalen Prompt-Guardrails.

Engineering Takeaway

Modelliere einen Agenten als nicht vollständig vertrauenswürdigen Software-Principal. Die Policy-Schicht muss technisch entscheiden, was ausgeführt werden darf; das Modell darf diese Entscheidung nicht selbst treffen.

NVIDIA investiert 3,5 Milliarden Dollar in MediaTek-Wandelanleihen. 🔬 KONZEPT DES TAGES~8 MIN

Scale-up vs. Scale-out: Warum AI-Cluster zwei Netzwerke brauchen

NVLink Fusion klingt nach Chip-Marketing. Dahinter steckt aber eine fundamentale Architekturfrage: Wie lässt man Tausende Accelerators so zusammenarbeiten, dass sie sich möglichst wie ein großer Rechner verhalten?

1 · Intuitiv erklärt

Stell dir eine Großküche vor. Scale-up bedeutet: Köche innerhalb derselben Küche können Zutaten praktisch ohne Verzögerung weiterreichen. Scale-out bedeutet: Mehrere Küchen arbeiten gemeinsam und schicken sich Lieferungen über Lastwagen. Beides erhöht Kapazität, aber Kommunikation innerhalb einer Küche ist viel enger und schneller.

Bei AI sind die „Köche“ GPUs oder andere XPUs. Große Modelle passen oft nicht auf einen Accelerator. Tensoren, Attention-Zustände oder MoE-Tokens müssen deshalb laufend zwischen Chips ausgetauscht werden. Wenn diese Kommunikation zu langsam ist, warten teure Recheneinheiten auf Daten.

2 · Technisch

Scale-up verbindet Accelerators innerhalb eines eng gekoppelten Systems mit sehr hoher Bandbreite und niedriger Latenz – etwa über NVLink/NVSwitch-artige Fabrics. Scale-out verbindet Nodes oder Racks über Datacenter-Netzwerke wie InfiniBand oder Ethernet/RDMA. Distributed Training und Inference verwenden je nach Parallelisierungsstrategie beide Ebenen.

        SCALE-UP DOMAIN
 GPU ─┬─ GPU ─┬─ Custom XPU
      │       │
   high-bandwidth fabric
      │       │
 GPU ─┴─ GPU ─┴─ XPU
          │
          │ scale-out network
          ▼
   another rack / node

Bei Tensor Parallelism müssen Chips innerhalb eines Layers häufig Daten austauschen – hohe Scale-up-Bandbreite ist kritisch. Pipeline Parallelism oder Data Parallelism können größere Distanzen tolerieren. Bei Mixture-of-Experts entsteht wiederum intensiver All-to-All-Verkehr, wenn Tokens zu unterschiedlichen Experts geroutet werden.

3 · Was NVLink Fusion strategisch macht

Custom Accelerators waren bisher ein Weg, NVIDIA teilweise zu umgehen. NVLink Fusion dreht diese Logik um: Ein Hyperscaler kann einen eigenen XPU entwickeln und ihn trotzdem in eine NVIDIA-definierte Scale-up-Fabric und Rack-Architektur integrieren. NVIDIA kann dadurch Systemkomponenten und Interconnect verkaufen, selbst wenn der Compute-Die von jemand anderem stammt.

Custom XPU
   │
NVLink Fusion chiplet
   │
NVLink scale-up fabric
   ├── NVIDIA GPU
   ├── another XPU
   ├── Rosa CPU
   └── shared high-bandwidth system
