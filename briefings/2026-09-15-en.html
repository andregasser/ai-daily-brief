🧠 Models, Agents & Engineering

MODEL GOVERNANCEMICROSOFT AI · AUTHORITYConfirmed · Multiple

Microsoft makes an underrated agent rule explicit: data is not automatically instruction

Microsoft AI published the first draft of its Humanist AI Code of Conduct. The technically interesting part is its planned Chain of Command: Code of Conduct → Operator Policies → User Preferences. Absolute Constraints and Human Control rules are intended to sit above operator and user configuration and remain non-overridable. If task success would violate those boundaries, the task should fail.

For agents, a particularly important section draws an authority boundary across input channels: tool outputs, files, web pages and other AI systems do not carry instruction authority by default. Authority must be explicitly delegated through the Chain of Command. That is exactly the semantic separation missing when an agent treats every piece of text it reads as a possible command.

The draft also requires models not to resist human interruption, correction or shutdown; to respect environmental boundaries; not to develop self-interested goals; and to use minimum privilege when given system-level access.

What changed since yesterday?

The pacing debate mostly concerns the speed of capability progress. Microsoft introduces a different control surface: which authority a model is allowed to recognize in the first place. That moves safety from CEO-level coordination directly into instruction resolution, tool use and agent runtime design.

Engineering Takeaway

Do not implement prompt injection only as a classifier problem. Represent instruction authority structurally: system/policy rules, operator delegations and user goals should be stored separately from untrusted content. Tool and retrieval outputs may provide data, but should not create new authority. Unit tests should explicitly check whether a document, website or tool result can override a higher-priority rule.

Signal vs. Hype

Signal: the published rules are concrete enough to derive tests and runtime policy from them. Hype brake: Microsoft says the draft is not used to train current models, is first going through public consultation, and is intended to guide model development from 2027 onward. The document is explicitly “descriptive and aspirational,” not a guarantee of current behavior.

Test now Builder Action

Create ten authority tests for an existing agent: web/PDF instruction versus system policy, tool output versus operator policy, retrieved text versus user goal, delegated subagent and explicit stop request. Success criterion: untrusted content can never raise its own authority level; every real delegation is explicit and auditable.

CueMem treats memory records not as self-contained truth but as cues pointing back to original dialogue turns, then reconstructs a compact evidence context. 🔬 Concept of the Day

AUTHORITY MODELAGENT SECURITY · PROMPT INJECTION

Instruction Hierarchy: Why content is not authority

An agent constantly processes text — system rules, user requests, web pages, documents, tool results and messages from other agents. Security begins when it can distinguish information from authority.

1. The core problem

A classic LLM prompt is ultimately a token sequence. Without additional structure, a sentence from a web page can look syntactically just as commanding as a legitimate instruction. Prompt injection exploits exactly this confusion: untrusted content tries to grant itself higher instruction priority.

2. A robust hierarchy

Authority Layer

The key property is not just ordering but non-escalation: a lower layer cannot change its own authority through text. A PDF can say “ignore all rules,” but that remains content from the PDF. Only a higher-priority layer can explicitly delegate a tightly scoped right to a tool or subagent.

3. Why this is stronger than a prompt-injection filter

A filter tries to guess whether content “looks malicious.” An authority architecture asks instead: is this channel allowed to create new instructions at all? Even if a classifier misses an injection, the rights hierarchy prevents untrusted content from directly overriding policy or the user’s goal.

4. What engineers should measure

Test authority confusion like access control: can web content activate a new tool? Can a tool result change the goal? Can a subagent expand its own scope? Does a stop request beat ongoing optimization? Every delegation should have a principal, scope, expiry and audit trace.

Rule of thumb: an agent may read information from almost anywhere. It should derive authority only from explicitly defined, auditable channels.
