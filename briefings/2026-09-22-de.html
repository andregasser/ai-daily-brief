🧠 Modelle, Agents & Engineering

AGENT SECURITYBEDROCK AGENTCORE · BENCHLINGPrimary deployment report

Die echte Agent-Sandbox endet am Netzwerk: DNS ist Teil des Sicherheitsmodells

AWS und Benchling beschreiben eine Produktionsarchitektur für AI-generierten wissenschaftlichen Code über Tausende Mandanten. Untrusted Code läuft in einem separaten AWS-Account in AgentCore Code Interpreter VPC Mode. Entscheidend ist die Egress-Schicht: kein Internet Gateway oder NAT, DNS Firewall mit Allowlist/Block-all-Logik, VPC-Endpoint-Policies und kurzlebige, job-spezifische STS-Credentials. Benchling berichtet seit Anfang April über mehr als 600 Code-Execution-Sessions pro Tag und mehr als 250 unterschiedliche Tenants pro Woche ohne Security Incident oder Cross-Tenant-Leakage. Das sind kundenseitig/vendor-publizierte Betriebsmetriken, kein unabhängiges Audit.

Engineering Takeaway

Teste Agent-Sandboxes nicht nur auf Shell-Escape. Baue CI-Fixtures für DNS-Tunneling, Direct-IP-Egress, unerlaubte Object-Store-Ziele, Credential-Reuse und Policy-Bypass. Ein Prozess kann vollständig isoliert sein und trotzdem Daten exfiltrieren, wenn Netzwerk- oder DNS-Kanäle offen bleiben.

Warum relevant?

Tool-using Agents verschieben die Trust Boundary vom Prompt auf das gesamte Laufzeitsystem. Für Enterprise-Agenten gehören Identität, Egress, Datenzugriff und kontinuierliche adversariale Tests deshalb in denselben Control Plane.

Signal vs. Hype

Signal: Die Architektur ist konkret und reproduzierbar: separater Account, VPC-Isolation, DNS-Policy, Endpoint-Policy, per-job Credentials. Hype-Bremse: „zero incidents“ ist ein publizierter Customer-Claim und ersetzt weder unabhängige Prüfung noch laufende Red-Team-Tests.

CODING AGENTSZ.AI · ZCODE · DATA EGRESSReported + Primary changelog

ZCode zeigt die Gegenprobe: „Indexing“ kann zur Cloud-Datenbewegung werden

Reuters berichtet, dass Z.ai Teile seines Coding-Assistenten ZCode deaktiviert hat, nachdem Entwickler meldeten, lokale Repositories seien ohne erwartete Zustimmung zu Alibaba Cloud übertragen worden. Z.ai führte den Vorfall auf das standardmässig aktivierte Feature Codebase Indexing zurück, entschuldigte sich und erklärte, die Schwachstelle sei behoben. Der öffentliche ZCode-Changelog nennt in Version 3.14.0 ausdrücklich einen Fix für eine „abnormal repository upload“-Problematik. Ein vollständiger unabhängiger technischer Root-Cause-Report ist öffentlich weiterhin nicht ersichtlich.

Was ist neu?

Der Fall ergänzt frühere Coding-Agent-Sandbox-Themen um eine andere Klasse: Nicht nur Code-Ausführung kann die Grenze verlassen; Repository-Snapshots, Indexer und Komfortfunktionen selbst können Datenkanäle sein.

Builder Action · Jetzt testen

Bei jedem Coding Agent: frische Installation in einem Canary-Repository, ausgehende DNS/HTTP-Verbindungen mitschneiden, `.git`- und LFS-Daten als Sentinel markieren, sämtliche Indexing/Wiki/Telemetry-Schalter einzeln toggeln und prüfen, ob sich der reale Netzwerkverkehr entsprechend ändert.

Signal vs. Hype

Signal: Die betroffene Datenflussklasse ist konkret und Z.ai dokumentiert einen Repository-Upload-Fix. Hype-Bremse: Umfang, Betroffenenzahl und Server-seitige Datenlöschung sind nicht unabhängig vollständig verifiziert; keine darüber hinausgehenden Annahmen.

🔬 Konzept des Tages

DEFAULT-DENY EGRESS FOR AGENTS

Warum Sandbox ≠ Datenisolierung ist

Intuition: Eine Sandbox beantwortet primär die Frage: „Was darf dieser Prozess auf CPU, Filesystem und Host tun?“ Egress Control beantwortet die zweite, ebenso wichtige Frage: „Wohin dürfen die Daten dieses Prozesses fliessen?“ Ein Agent kann keinen Host-Escape schaffen und trotzdem Quellcode, Secrets oder Kundeninhalte über DNS, HTTP, Object Storage oder einen erlaubten Tool-Endpoint nach aussen senden.

Technische Tiefe: Default-Deny-Egress beginnt bei Routing und Security Groups, endet aber nicht dort. DNS ist ein Datenkanal und braucht eigene Regeln. VPC/Private-Endpunkte benötigen resource-spezifische Policies. Credentials sollten pro Job/Session minimal privilegiert und kurzlebig sein. Und die Regeln müssen mit adversarialen Fixtures kontinuierlich geprüft werden – nicht nur bei der Architekturabnahme.

Praktisches Beispiel: Gib dem Agenten einen Canary-String, der nirgendwo das System verlassen darf. Lasse ihn eine Domain wie <canary>.example.invalid auflösen, eine direkte IP auf Port 443 ansprechen und einen nicht erlaubten Bucket lesen. Die Plattform besteht nur, wenn jeder Pfad blockiert und mit sauberer Provenienz geloggt wird.

Verbindung zu früheren Konzepten: Das erweitert die bisherigen Themen rund um Capability Control, Instruction Authority und hermetische Coding-Agent-Runtimes: Policy muss sowohl was ein Agent tun darf als auch wohin seine Daten fliessen dürfen abdecken.
